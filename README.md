# DGT PWA — тренажёр теории DGT для русско- и армяноговорящих

Минималистичное PWA: 90 тестов по 30 вопросов, пояснение сразу после ответа, перевод любого вопроса на RU/HY в один тап, раздел «Ошибки» (по 5 вопросов), вход через Telegram, бот с «вопросом дня», оплата 50 € за 100 дней с гарантией «до сдачи», админка для правки всего.

Стек: Next.js 14 (App Router) · TypeScript · Tailwind · Postgres (Supabase) · Stripe · Telegram Bot API. Всё бесплатно стартует на GitHub + Vercel + Supabase.

---

## 1. Запуск у себя (5 минут, без внешних сервисов)

```bash
npm i
cp .env.example .env.local
# в .env.local: SESSION_SECRET=<openssl rand -hex 32>, ADMIN_TELEGRAM_IDS=9001, ENABLE_DEV_LOGIN=true
npm run db:seed        # 30 демо-вопросов и 3 теста (локальная встроенная БД в папке .data)
npm run dev            # http://localhost:3000
```

На `/login` появится кнопка «Войти как разработчик» (ID 9001 — это админ). Админка: `/admin`.

Проверки: `npm test` (79 тестов правил, бота, оплаты, админки, конвертера), `npm run lint` (типы), `npm run build && npm start` + `npm run e2e` (сквозной прогон в браузере; нужен Chromium, путь в `CHROMIUM=`).

## 2. Два раздела тестов: «Официальные» и «Дополнительные»

С сентября 2026 в меню `/test` — два независимых раздела (`TestCategory`: `official` / `mixed`), у каждого своя нумерация (в обоих может быть «Тест 1»):

- **«Официальные тесты DGT»** (`category: 'official'`) — основной платный тренажёр: разблокировка по порядку, первый тест (или `FREE_TESTS`) бесплатно, дальше — подписка (50 €/100 дней), права на вопросы проверяются (`unverified` скрыт, если не включён `SERVE_UNVERIFIED_QUESTIONS`). Сюда же попадает набор `dgt-official.json` (см. 2а) и все ваши собственные вопросы. Именно этот раздел растёт по мере того, как вы добавляете тесты сами.
- **«Дополнительные тесты»** (`category: 'mixed'`) — по вашему явному решению показываются **всем посетителям сайта без ограничений**: без блокировки по порядку, без оплаты, без проверки статуса прав (даже `unverified` виден и играбелен). Сюда попадает набор LordOkami/TodoTest (см. ниже). Раздел вообще не отображается в меню, если в нём нет тестов.

⚠️ Напоминание (коротко, без повтора всей юридической части — см. раздел 6): вопросы LordOkami/TodoTest собраны из TodoTest, чьи условия использования запрещают коммерческое копирование, а у самого репозитория LordOkami нет лицензии. Раздел «Дополнительные тесты» открыт по вашему прямому указанию («все посетители сайта», названо специально нейтрально — не «авторские», чтобы не выдавать чужой контент за собственный) — это осознанный юридический риск, который вы приняли; технических ограничений на нём больше нет.

### Загрузка вопросов LordOkami (раздел «Дополнительные тесты»)

```bash
# 1) склонируйте репозиторий LordOkami рядом с проектом
git clone https://github.com/LordOkami/dgt-b-scrapper.git ../dgt-b-scrapper
# 2) конвертация: 90 тестов × 30 вопросов = 2133 уникальных вопроса, 854 картинки → public/q-images
#    (тесты автоматически помечаются category: "mixed")
npm run lordokami:convert -- ../dgt-b-scrapper/data/todotest_b --out data/lordokami.json
# 3) проверить без записи и загрузить (вопросы + состав всех 90 тестов)
npm run questions:import -- data/lordokami.json --dry
npm run questions:import -- data/lordokami.json
npm run dev   # раздел «Дополнительные тесты» сразу открыт всем — без SERVE_UNVERIFIED_QUESTIONS/UNLOCK_ALL_TESTS
```

Что важно про эту выгрузку (проверено на реальных файлах):

- Текст в исходных JSON сохранён с «двойной» кодировкой (`Â¿`, `Ã­`) — конвертер это исправляет.
- 46 вопросов имеют только **два** варианта ответа — приложение это поддерживает (пустой вариант C в испанском оригинале = вопрос из двух вариантов).
- **Пояснений в выгрузке нет**, перевода на RU/EN/HY тоже (только испанский текст). Их нужно добавить: вручную в админке либо отдельным скриптом машинного перевода.
- Темы расставлены автоматически по ключевым словам (`senales`, `velocidad`, …) — это черновик, правьте в `/admin/topics` и в карточке вопроса.
- `data/lordokami.json` и `public/q-images/` добавлены в `.gitignore` — просто чтобы не раздувать git большой авто-выгрузкой (её несложно перегенерировать скриптом); на показ пользователям это не влияет, раздел «Дополнительные тесты» их видит независимо от того, закоммичен файл или нет.

### 2а. Официальный набор DGT (раздел «Официальные тесты DGT»)

В том же репозитории лежит выгрузка публичного симулятора DGT: он выдаёт всего **3 разных экзамена = 90 вопросов** с правильными ответами и картинками. Они получают статус `dgt_official` и `category: 'official'`, показываются пользователям без флага `SERVE_UNVERIFIED_QUESTIONS`, а в плеере под вопросом выводится ссылка на источник. Именно этот раздел вы, по своим словам, будете дальше пополнять своими тестами.

```bash
npm run dgt:convert -- ../dgt-b-scrapper/data     # → data/dgt-official.json + картинки в public/dgt-images
npm run questions:import -- data/dgt-official.json  # тесты №1–3 (3 экзамена DGT, category: official)
#   --first-test N в dgt:convert — с какого номера нумеровать тесты
```

Условия DGT для повторного использования (страница «Derechos sobre la Propiedad intelectual» на sede.dgt.gob.es, проверено): указывать источник (Organismo Autónomo Jefatura Central de Tráfico), не менять содержание, а при продаже сообщать покупателю **до и во время оплаты**, что информацию можно получить бесплатно на сайте DGT. Всё это уже сделано: подпись в плеере, текст на странице оплаты (`lib/legal-notes.ts`), тот же текст в окне Stripe Checkout, раздел 4 в `/legal`. Поэтому вопрос `dgt_official` править нельзя (админка предупреждает) — правите, только переведя его в `own`. Переводы и пояснения добавлять можно. Замечание: текст на сайте DGT про симуляторы экзамена отдельно не говорит, и DGT оставляет за собой права на тексты и изображения — покажите этот пункт юристу/gestor.

**Как это соотносится друг с другом:** оба набора можно держать в одной базе одновременно (проверено: составные ключи `(category, number)` не конфликтуют) — официальный набор (DGT + ваши `own`-вопросы) в разделе «Официальные тесты DGT», LordOkami — в «Дополнительных». Если через какое-то время вы перепишете часть вопросов LordOkami своими словами и переведёте их в `own`, логичнее всего добавить их в раздел `official` отдельным тестом, а не оставлять дубль в `mixed`.

В админке (`/admin`):

- **Вопросы** — поиск, фильтры (права, тема, тест, «нет перевода», «машинный перевод»), массовые действия; редактор: формулировка, три варианта, правильный ответ, пояснение, картинка (URL или загрузка), тема, 4 языка (ES/EN/RU/HY) с отметкой «проверено человеком».
- **Темы** — переименование (совпавшие темы сливаются).
- **Тесты** — какой вопрос в каком слоте теста 1–90; автосборка недостающих тестов.
- **Импорт / экспорт** — JSON (`dgt-pwa/questions@1`, вместе с составом тестов), проверка перед загрузкой.
- **Пользователи** — выдать дни; **Гарантия** — заявки по экзамену, отзыв заявки.

Правки видны пользователям сразу. Когда вы «уникализируете» вопрос, переведите права в `own` (написан мной), тогда он станет доступен на боевом сайте.

Формат импорта (кратко):

```json
{
  "format": "dgt-pwa/questions@1",
  "questions": [
    { "source": "manual", "source_ref": "q-001", "rights_status": "own", "topic": "velocidad",
      "correct": "b", "image_url": null, "is_active": true,
      "i18n": {
        "es": { "text": "…", "a": "…", "b": "…", "c": "…", "explanation": "…", "status": "reviewed" },
        "ru": { "text": "…", "a": "…", "b": "…", "c": "…", "explanation": "…", "status": "machine" } } }
  ],
  "tests": [ { "number": 1, "category": "official", "refs": ["q-001", "q-002"] } ]
}
```

`refs` — это `source_ref` вопросов по порядку позиций в тесте. `category` — `official` или `mixed` (см. раздел 2); можно не указывать — тогда тест попадёт в `official`. Готовый пример — `data/seed-questions.json`.

Повторный импорт обновляет вопросы по `source + source_ref`, дубликатов не создаёт.

## 3. Выкладка: GitHub + Vercel + Supabase

1. **GitHub**: создайте приватный репозиторий и залейте проект (без `node_modules`, `.next`, `.data` — они в `.gitignore`).
2. **Supabase**: New project → SQL Editor → по очереди вставьте и выполните все файлы из `supabase/migrations/` **по порядку номеров** (`001_init.sql`, затем `002_test_categories.sql`) → Run. Если сайт уже был выложен раньше на `001_init.sql` — просто примените `002_test_categories.sql` так же через SQL Editor, он безопасен для базы с данными (только добавляет колонку `category`/`test_category` и меняет первичные/внешние ключи, ничего не удаляет). Затем Project Settings → Database → Connection string → **Transaction pooler** → это `DATABASE_URL`. (Приложение ходит в БД только с сервера; RLS включён без политик, публичный ключ Supabase ничего не даёт.) Для картинок: Storage → создайте публичный bucket `question-images`, в env добавьте `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
3. **Vercel**: Import репозитория, добавьте переменные из `.env.example` (см. ниже). Deploy.
4. **Telegram**: @BotFather → `/newbot` → токен и username в `TELEGRAM_BOT_TOKEN` и `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`; `/setdomain` → ваш домен Vercel (без этого виджет входа не работает). Свой ID узнайте у @userinfobot → `ADMIN_TELEGRAM_IDS`. Затем локально с боевыми env: `npm run bot:webhook` (регистрирует вебхук со `TELEGRAM_WEBHOOK_SECRET`). Команды бота: `/start`, `/question`, `/stats`, `/stop`.
5. **Stripe**: секретный ключ → `STRIPE_SECRET_KEY`. Developers → Webhooks → endpoint `https://<домен>/api/stripe/webhook`, события `checkout.session.completed` и `checkout.session.async_payment_succeeded` → подпись в `STRIPE_WEBHOOK_SECRET`. Сначала проверьте на тестовых ключах (карта 4242 4242 4242 4242).
6. **Cron «вопрос дня»**: `vercel.json` запускает `/api/cron/daily` в 07:00 UTC; задайте `CRON_SECRET` (Vercel подставит его в заголовок сам). На тарифе Hobby cron — раз в сутки, точное время не гарантируется (окно в пределах часа).

Обязательно на боевом сайте: `ENABLE_DEV_LOGIN=false`, `SERVE_UNVERIFIED_QUESTIONS=false`, `NEXT_PUBLIC_SITE_URL=https://<домен>`, длинный `SESSION_SECRET`.

## 4. Правила (всё в `lib/engine.ts`, покрыто тестами)

- 0 ошибок → следующий тест открыт. ≤ 2 ошибок → эти вопросы тут же решаются отдельно и сохраняются в «Ошибки», следующий тест открыт. > 2 ошибок → следующий закрыт, пока в этом тесте не будет ≤ 2.
- «Ошибки»: каждый неверный ответ запоминается; заход даёт 5 вопросов (сначала давно не показанные, затем самые «проблемные»). Верный ответ в разделе снимает вопрос с очереди, неверный — увеличивает счётчик.
- Доступ (раздел «Официальные тесты DGT»): первые `FREE_TESTS` тестов бесплатно (по умолчанию 1), раздел «Ошибки» и остальные тесты — по подписке. 50 € = 100 дней, без автопродления. Раздел «Дополнительные тесты» — вне этих правил, целиком бесплатен и открыт всем (см. раздел 2).
- Гарантия: после оплаты в профиле можно указать результат экзамена. «Не сдал» → доступ +30 дней (можно повторять); «сдал» → гарантия закрыта. Одна и та же дата экзамена дважды не принимается; админ может отозвать заявку.

## 5. Ограничения и что знать

- Вход — собственная подписанная cookie (Telegram Login Widget проверяется на сервере), а не Supabase Auth: так БД остаётся закрытой для публичного ключа.
- PWA: устанавливается на экран; офлайн работает только страница-заглушка (тесты требуют сети, чтобы не отдавать устаревшие вопросы).
- Интерфейс (кнопки, подписи) пока только на русском; на армянский и английский переводится содержимое вопросов.
- Переводы на RU/EN/HY в демо-наборе — машинные черновики; армянский особенно нужно вычитать. Демо-вопросы (30 шт., `own`) написаны заново и требуют сверки с актуальным RGC/LSV перед публикацией.
- Не реализовано / не проверено на реальных сервисах: боевой Stripe Checkout, боевой вход и бот Telegram, подключение к Supabase pooler (локально всё проверено на настоящем Postgres — PGlite — и в Chromium).

## 6. Юридически (не юридическая консультация)

- Раздел «Дополнительные тесты» (LordOkami/TodoTest, статус `unverified`) по вашему явному решению открыт всем посетителям сайта бесплатно, без каких-либо технических ограничений — это было сознательно сделано по вашей инструкции. Напоминаю факты, на которых основана эта развилка, без давления на решение: условия TodoTest запрещают коммерческое копирование, у репозитория LordOkami нет лицензии, и его данные собраны из TodoTest — то есть юридический риск при публичном показе этого раздела сохраняется, просто он больше не смягчён техническим скрытием контента. Если решите снизить риск позже — самый надёжный путь: переписывать вопросы своими словами по тексту закона (RGC/LSV — тексты законов свободны) и переводить их в `own` в разделе «Официальные тесты DGT», либо ограничить видимость раздела `mixed` на уровне кода (сейчас он открыт для всех по коду в `lib/repo/content.ts`/`lib/engine.ts` — правки нужно вносить туда).
- Официальные материалы DGT (раздел «Официальные тесты DGT», `dgt_official`) — только с указанием источника и без изменений, с пометкой для покупателей.
- Не используйте DGT в названии и логотипе как основной бренд, чтобы не создавать впечатление официального сервиса.
- Продажа физлицам в ЕС: согласие на немедленное предоставление и отказ от desistimiento реализовано галочкой перед оплатой; текст условий (`/legal`) проверьте у юриста/gestor. Как autónomo — проверьте IVA/OSS для платежей из других стран ЕС.
